# 不再忍受飞秋的古老界面——倍信让局域网聊天回到2026

## 你每天用的聊天工具，界面还停在2008？

飞秋（FeiQ）可能是中国办公室里最常见的局域网聊天工具。它简单、免费、能传文件——这些优点让它在十几年前就占领了无数办公桌。但这么多年过去了，飞秋的界面几乎没变过：Delphi 写的古典风格窗口、挤在一起的聊天消息、没有历史记录、不支持图片……

这不是飞秋的错，它诞生于一个不同的时代。但时代变了，我们的需求也变了。

**倍信（IPMsg Pro）** 是一款全新的局域网聊天工具，它保留了飞秋的核心价值（局域网通讯、文件传输），但把用户体验拉到了 2026 年的水平。

## 倍信做了什么飞秋做不到的事？

### 📸 图片聊天

飞秋不支持发图片。你要截图保存到文件，再用文件传输发过去，对方还要手动找到文件打开。倍信直接支持**图片发送**——选图预览确认，对方收到缩略图，点击查看原图。就像微信发图一样自然。

### 💬 消息历史

飞秋关掉窗口消息就消失。倍信所有消息**自动持久化到 SQLite 数据库**，随时回看历史对话，搜索关键词定位特定消息。错过同事发的通知？打开历史记录找就行。

### ✅ 送达确认

飞秋发文字消息，你永远不知道对方是不是收到了。倍信文字消息也有**送达回执**——发出去的消息状态从"发送中"变为"已送达"，确认不遗漏。

### 📁 文件传输进化

飞秋传文件的体验：一个进度条+一个保存路径。传完了想找文件？翻文件夹去吧。倍信的文件传输：

- 接收前确认（不想收可以直接拒绝）
- 实时进度条（不只是动画，是真实进度）
- **一键打开文件夹**（传完直接看到文件在哪）

### 🌐 多网段发现

飞秋只能发现同一子网的用户。跨网段要手动加好友。倍信支持**配置 IP 范围自动扫描**，设定好友网段后自动发现不同子网的用户，无需手动操作。

## 最关键的一点：完全兼容飞秋

你可能担心："我换了倍信，但同事还在用飞秋，能互通吗？"

**完全互通。**

倍信完整实现了 IPMsg v3.0 协议，并且对飞秋的特殊协议行为做了逐一适配：

| 飞秋特殊行为 | 倍信的适配 |
|---|---|
| 飞秋发送 GBK 编码 | 倍信自动识别并转换为 UTF-8 显示 |
| 倍信发给飞秋 | 自动降级为 GBK 编码，飞秋正常显示 |
| 飞秋文件请求格式差异 | 兼容飞秋不含 `\0` 分隔符的请求格式 |
| 飞秋扩展版本号 | 正确识别飞秋的扩展版本信息 |
| 飞秋不支持 UTF8OPT | 文件消息不发 UTF8OPT 标记，确保飞秋兼容 |

**你装倍信，同事继续用飞秋，一切照常运转。** 等他们看到你的聊天界面，自然会想换。

## 技术架构：为什么倍信能做到这些？

倍信的技术选型让它既能实现现代化 UI，又能保持轻量部署：

- **前端 React + TypeScript** — 现代化 UI 框架，组件化开发，类微信交互
- **后端 C++17** — 高性能网络通讯，直接调用 Win32 API，无中间层损耗
- **WebView2 渲染** — 利用系统 Edge 运行时，不自带浏览器引擎，体积小
- **单 exe 打包** — 前端资源嵌入 exe，零安装依赖，复制即用
- **前后端 Bridge** — JSON-RPC 通信，前端调 C++ 命令如同调 API

这套架构让倍信的 exe 体积控制在合理范围（约 2MB），同时提供了远超飞秋的界面表现力。

## 安全：数据不离开局域网

倍信是**纯局域网通讯工具**。所有消息、文件、用户数据都在局域网内传输，不经过任何云端服务器。你的聊天内容不会被任何第三方获取。
